# Ежедневный чат: изменения UI/UX

Изменения продолжают аудит стабильности в PR №5. Интерфейс сохраняет текущую структуру продукта, но убирает лишние действия из основного сценария.

## Пользовательский результат

- Компактное поле ввода без прыжков при фокусе, кнопка отправки со стрелкой вверх, отдельная кнопка Stop во время ответа. На сенсорном экране Enter создаёт строку; на компьютере Enter отправляет, Shift+Enter создаёт строку. IME-композиция не отправляет сообщение.
- Боковое меню на мобильном скрывается полностью и открывается поверх страницы. Оно не перекрывает текст в закрытом состоянии; фон исключён из клавиатурного фокуса, Escape закрывает меню. Мобильные переключения не перезаписывают предпочтение боковой панели для компьютера.
- Переименование чата открывает диалог интерфейса с текущим названием, Escape и восстановлением фокуса.
- Второстепенные разделы доступны через «Ещё разделы». Поиск и материалы текущего чата находятся в шапке. Ход подготовки ответа свёрнут в компактную строку с раскрываемыми деталями.
- Запоздавший ответ загрузки чата больше не заменяет выбранный позже диалог или новый чат. Черновик и история переключаются вместе. До загрузки черновика автоматическое сохранение не запускается.
- Записи и очистка серверного черновика выполняются последовательно для каждого чата; один чат не блокирует другой. Первый серверный PUT блокирует родительский Conversation даже при отсутствии Draft, чтобы избежать гонки создания уникальной записи.
- Одно и то же действие Stop работает для текущего потока и для ответа, восстановленного после перезагрузки. Ошибка отмены видна пользователю. Редактирование и повтор ответа недоступны, пока предыдущий запрос выполняется.
- Подтверждение дорогого запроса выполняется в диалоге интерфейса с максимальной суммой, клавиатурным фокусом и отменой по Escape. Отмена сохраняет исходный запрос и не показывает сообщение об ошибке.
- Поиск отменяет устаревшие запросы и не показывает результат прежнего запроса после очистки строки. Ошибки действий в истории отображаются в интерфейсе.
- Вложения автоматически обновляют статус обработки. Отправка ждёт готовности файла, а черновик остаётся доступен для редактирования. Ошибка файла объясняет, как продолжить; пятый файл не загружается впустую.
- Прокрутка следует за ответом, пока пользователь читает снизу, и сохраняет положение при чтении выше. Таблицы не поглощаются предыдущим абзацем; нумерованные списки сохраняют начальное число; копирование кода сообщает об отказе браузера, а блок кода не пересоздаётся при каждом токене.

## Проверка

- **12 frontend regression tests passed**: транспорт/SSE, snapshots, идентичность сообщений, навигация, очередь сохранения черновиков, готовность вложений.
- **8 browser scenarios passed на production-сборке Chromium**: загрузка черновика/границы окна; быстрые переключения; поиск/устаревшие ответы/Escape; отмена и подтверждение цены/единственный ответ; обработка файла при редактируемом черновике; обычный Stop; Stop после перезагрузки; мобильное меню/Enter/offline.
- **12 backend tests passed**: черновики/изоляция пользователя, кабинет, пользовательский путь, отмена, подтверждение цены, статус генерации.
- PostgreSQL concurrency regression добавлен в общий reliability gate. В локальном SQLite-прогоне он пропускается: SQLite не подтверждает корректность PostgreSQL row locks.
- TypeScript, production frontend build, Ruff для изменённых Python-файлов, Django check и git diff --check проходят.

Запуск frontend-проверок:

```bash
cd frontend
npm ci
npm run test:chat
npx playwright install chromium
npm run build
npm run start
# В другом терминале, при работающем сервере:
npm run test:ux
```

`CHAT_UX_BASE_URL` позволяет выбрать адрес локального тестового frontend. Browser tests подменяют API ответами фикстур; они проверяют настоящий интерфейс и транспорт браузера, но не доступность реального LLM-провайдера. В тесты не передаются клиентские данные и платные ключи.

## Границы результата

Изменения опубликованы для review и не развёрнуты на production. Safari/iOS и Android с реальной экранной клавиатурой требуют проверки на устройствах. Production LLM, прокси, PostgreSQL/Redis и оставшиеся результаты общего аудита из `CHAT_RELIABILITY_AUDIT_2026_10_01.md` не объявляются проверенными этими UI-тестами.
