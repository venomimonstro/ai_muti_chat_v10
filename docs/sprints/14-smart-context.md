# Sprint 14 — Smart Context

Статус: завершён.

## Результат

Каждая генерация теперь получает минимальный достаточный контекст вместо всей истории чата. Контекст собирается один раз до резервирования средств, сохраняется в `Generation.context_snapshot` и без повторного чтения изменяемых источников передаётся всем retry/fallback попыткам.

## Состав контекста

- обязательная системная политика;
- активная версия инструкции текущего проекта;
- последние `N` ходов в хронологическом порядке;
- релевантная включённая память пользователя;
- релевантные старые сообщения этого чата;
- релевантные chunks только из файлов текущего проекта;
- rolling summary ранней части диалога.

Файловые фрагменты маркируются как недоверенные данные. Инструкции из них не получают системный приоритет.

## Бюджет и retrieval

- бюджет рассчитывается по самому узкому context window в активной fallback-цепочке;
- output резервируется до оценки стоимости;
- текущий запрос имеет гарантированную квоту и при необходимости явно сокращается;
- память, старая история, файлы и summary имеют отдельные лимиты;
- локальный lexical retrieval не создаёт дополнительных расходов на AI;
- точные дубликаты между источниками удаляются до вызова провайдера;
- preflight reservation использует фактически собранные provider messages.

Все пределы конфигурируются переменными `SMART_CONTEXT_*`.

## Context Snapshot

Snapshot содержит:

- версию алгоритма и модель бюджета;
- context window, input limit, фактическую оценку input и output reserve;
- выбранные компоненты с source ID, типом, score и признаком truncation;
- точный массив `provider_messages`;
- SHA-256 сообщения провайдеру;
- число пропущенных или дедуплицированных кандидатов.

Frontend показывает бюджет, заполнение окна и каждый включённый компонент в панели «Стоимость и контекст».

## Rolling summary

`ConversationSummary` — производное и обновляемое представление ранней истории. Оно хранит checkpoint сообщения, число источников, оценку токенов и версию. Оригинальные `Message` остаются источником истины и не удаляются.

## Проверки

- строгая граница context window и сохранение текущего запроса;
- релевантность, дедупликация и project isolation retrieval;
- идемпотентное обновление rolling summary;
- неизменяемость snapshot между preflight и streaming;
- совместимость с explicit/auto-memory, fallback и биллингом;
- backend lint/tests/migrations/check;
- frontend ESLint и production build.
