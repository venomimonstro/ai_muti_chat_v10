# Sprint 21 — Compare + Branches

## Результат

Пользователь выбирает 2–4 доступные текстовые модели, заранее видит диапазон стоимости и запускает
их параллельно для одного запроса. Любой ответ можно превратить в отдельную ветку, не меняя
исходную историю. После сравнения можно сформировать единый итоговый ответ.

## Cost protection

До provider call система рассчитывает minimum/maximum для каждой модели через versioned Price,
FX, markup hierarchy и Margin Guard. Верхняя граница суммируется и атомарно резервируется одним
hard limit. После завершения списывается только фактическая сумма успешных вариантов, остаток
возвращается в paid/promo buckets.

Дорогой Compare и synthesis требуют явного подтверждения. Порог задаётся
`COMPARE_CONFIRM_THRESHOLD_RUB`. Запуск Compare требует `Idempotency-Key`, поэтому повтор HTTP
запроса не создаёт второе списание.

## Parallel generations

Каждая модель получает одинаковый prompt и собственный immutable pricing snapshot. Provider calls
выполняются параллельно, а результаты сохраняются независимо. Ошибка одной модели переводит run в
`partial`, не уничтожая успешные ответы. Вариант хранит токены, latency, фактическую стоимость,
provider request id и безопасный error code.

## Branch model

У каждого чата есть основная и активная ветка. Новая ветка сохраняет IDs унаследованных сообщений
строго до точки fork; новые сообщения принадлежат только ей. Переключатель веток восстанавливает
видимую историю, Smart Context и semantic search продолжают работать с сохранёнными сообщениями.

Ветку можно создать от обычного сообщения или успешного Compare-варианта. Исходные сообщения и
ответы не редактируются и не удаляются.

## Synthesis

Опциональный synthesis использует только успешные варианты и отдельный cost preview/reservation.
Повтор завершённого запроса возвращает сохранённый итог без повторного provider call.
