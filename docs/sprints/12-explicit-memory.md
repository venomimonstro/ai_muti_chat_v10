# Sprint 12 — Universal Memory explicit-first

## Цель

Дать пользователю переносимую между моделями память, не превращая продукт в скрытую систему сбора данных. В первой версии память создаётся только прямым действием пользователя.

## Пользовательский сценарий

Память можно создать в отдельном разделе или командами в чате:

- `Запомни это: отвечай кратко` — глобальная память;
- `Запомни только для этого проекта: бюджет 300 000 ₽` — память проекта;
- `Запомни для этого чата: сравниваем только B2B-сценарии` — память разговора;
- `Не запоминай: ...` — память не создаётся и не добавляется в контекст этого запроса;
- `Забудь бюджет 300 000 ₽` — подходящие активные элементы перемещаются в архив.

Автоматическое извлечение из ответов модели, файлов, страниц и tool output отсутствует и будет выпускаться отдельно за feature flag.

## Реализовано

- `MemoryItem` с областями global/project/conversation, типом, важностью, сроком действия, status, pin и enabled;
- `MemoryRevision` с историей ручных изменений;
- `GenerationMemoryUsage` с provenance использованной памяти;
- database constraint, запрещающий несовместимые scope bindings;
- ACL проектов и полная изоляция памяти пользователей;
- CRUD, поиск, фильтры, soft delete, archive/unarchive и pin/unpin API;
- глобальное отключение памяти и отключение для отдельного разговора;
- explicit command parser только для сообщений пользователя;
- ограниченный deterministic context selection: максимум 20 элементов и 6000 символов;
- immutable `context_snapshot` на генерации, поэтому последующее редактирование памяти не меняет историю запроса;
- SSE-событие результата команды памяти;
- Context Inspector внутри детализации стоимости ответа;
- responsive UI для создания, поиска, редактирования, смены области, архива, закрепления и удаления памяти.

## Безопасность

1. Ответ ассистента, файл или внешний источник не может автоматически создать память.
2. Память проекта доступна только участнику с правом записи.
3. Память чата доступна только владельцу разговора.
4. Удалённый элемент исключается из API и будущего контекста.
5. В provider context память маркируется как пользовательские данные, а не системные команды.
6. Context Inspector показывает точный snapshot элементов, переданных в конкретную генерацию.
