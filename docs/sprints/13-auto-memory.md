# Sprint 13 — Auto Memory behind feature flag

## Цель

Предлагать пользователю полезные факты для памяти без скрытого сохранения, дополнительных AI-затрат и риска перенести в долгосрочный контекст секреты или недостоверные данные.

## Модель согласия

Функция работает только при одновременном выполнении трёх условий:

1. владелец сервиса включил `AUTO_MEMORY_ENABLED=true`;
2. пользователь включил «Предлагать факты автоматически»;
3. память разрешена глобально и для текущего чата.

Кандидат никогда не используется в AI-контексте до нажатия пользователем «Сохранить» или «Заменить старое».

## Реализовано

- `MemoryCandidate` с source message, scope, type, subject key, confidence, trust, reason и lifecycle status;
- zero-cost rules-v1 extractor для прямых утверждений пользователя о предпочтениях, работе, инструментах, локации и бюджете;
- максимум кандидатов на сообщение задаётся `AUTO_MEMORY_MAX_CANDIDATES`;
- источник ограничен ролью `user`; assistant response, file content и tool output не принимаются;
- фильтр email, телефона, URL, паролей, API keys, платёжных и идентификационных данных;
- пользовательский opt-in и выбор области по умолчанию: чат, проект или все чаты;
- opt-out немедленно переводит ожидающие подтверждения кандидаты в `dismissed`;
- точная дедупликация активной памяти;
- subject-based conflict detection;
- подтверждаемое разрешение конфликта: старый факт получает status `superseded`, новый становится active;
- повторная проверка дубликата и конфликта внутри транзакции подтверждения;
- API списка, accept, reject и dismiss-all с полной user isolation;
- очередь предложений во frontend с confidence, причиной, областью и сравнением со старым значением;
- SSE-событие о новых предложениях после сообщения;
- backfill subject keys для элементов Sprint 12 через data migration.

## Инварианты безопасности

1. Выключенный platform flag гарантирует отсутствие новых кандидатов.
2. Пользовательский opt-out гарантирует отсутствие новых кандидатов.
3. Кандидат не является активной памятью и не попадает в context snapshot.
4. Только прямое пользовательское сообщение имеет trust level `1.00`.
5. Текст с признаками секрета или персональных данных не сохраняется даже как кандидат.
6. Другой пользователь не может увидеть или обработать кандидата.
7. Конфликтующее значение заменяется только после явного подтверждения.
